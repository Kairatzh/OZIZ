# Архитектура платформы OZIZ

## 1. Концепция и цель
**OZIZ** — децентрализованная GPS-платформа гражданского контроля городской инфраструктуры.
Цель: исключить замалчивание, «тихое» удаление или подмену обращений жителей государственными органами за счет фиксации каждого шага жизненного цикла жалобы в неизменяемом блокчейн-реестре на **Solana**.

## 3. Ключевые компоненты

### 3.1 Прием обращения (Frontend 3-Touch)
1. **Касание 1: Фотофиксация** — захват через камеру или выбор файла. На клиенте в HTML5 Canvas происходит масштабирование до 1600px, конвертация в JPEG (автоматически сбрасывающая бинарные EXIF-теги с приватными метаданными устройства).
2. **Касание 2: Геолокация** — вызов `navigator.geolocation` с `enableHighAccuracy`. Если радиус точности превышает 50 м, отображается предупреждение для ручной корректировки метки на карте.
3. **Касание 3: Отправка** — опциональный ввод комментария или голосовой набор через Web Speech API и моментальная отправка.

### 3.2 Мультимодальный ИИ-пайплайн (Gemini 3.8 Flash)
- Изображение + текст заявителя + геокоординаты передаются в модель с системным промптом эксперта городской инфраструктуры.
- Ответ валидируется по строгой схеме (категория, тяжесть 1..5, габариты, согласованность фото и текста, экстренный статус).
- При недоступности ключа API задействуется отказоустойчивый эвристический модуль.

### 3.3 Обогащение метеоконтекстом (Open-Meteo)
- Бесплатный геозапрос по координатам без API-ключа.
- Кеширование на координатную сетку с TTL 15 минут.
- Параметры: осадки (мм), температура, скорость ветра, прогноз (гололед, заморозки, дождь).

### 3.4 Формула объяснимого приоритета
Приоритет рассчитывается детерминированно:
$$\text{Priority Score} = \left( \sum w_i \cdot \text{Factor}_i \right) \times \text{Confidence Multiplier}$$

Факторы:
- $w_1 = 25$ — тяжесть по оценке ИИ (1..5)
- $w_2 = 20$ — близость к уязвимым объектам (школы, больницы, магистрали)
- $w_3 = 15$ — метеоусловия (дождь/мороз повышают риск ДТП)
- $w_4 = 10$ — интенсивность дорожного движения и час пик
- $w_5 = 15$ — подтверждения жителей («Я тоже вижу»)
- $w_6 = 10$ — возраст нерешенной проблемы (рост со временем)
- $w_7 = 25$ — бонус аварийности (`is_emergency`)

### 3.5 Смарт-контракт Solana (Anchor)
- **Отсутствие функций `update`, `delete`, `close`**: созданную запись нельзя стереть или изменить задним числом.
- **Хэш-цепочка статусов**: каждое новое событие ссылается на хэш предыдущего (`prev_event_hash`). Нарушение порядка или подмена данных обнаруживаются моментально.
- **Обязательное обоснование отклонения**: статус `REJECTED` принимается контрактом **только при наличии ненулевого хэша причины**.
